# Arquitectura propuesta (alto nivel)

* **Frontend/Backend monolito**: Next.js 15 (App Router), React Server Components, **Server Actions** para mutaciones simples, **Route Handlers** para integraciones (PDF/WhatsApp).
* **DB**: **PostgreSQL** (Neon, Supabase o RDS según despliegue). ORM **Prisma**.
* **Auth**: **Auth.js (NextAuth)** con email+password (privado) y posibilidad de agregar OAuth más adelante.
* **UI/Design system**: Tailwind + **shadcn/ui** (se monta local; luego extraemos a lib). Tokens de diseño desde el día 1.
* **Gráficos**: Recharts o Chart.js (client components aislados).
* **Exportables**:

  * **PDF** server-side (Playwright + headless Chromium en función serverless compatible; alternativa @react-pdf si prefieres 100% JS).
  * **Screenshot**: Playwright a una ruta protegida con query (render estático de la vista).
* **Mensajería WhatsApp**: wrapper para **Twilio** (o WATI/Meta Cloud API), disparo manual desde UI.
* **Deploy**: **Vercel** (staging desde `develop`, producción desde `main`). DB gestionada (Neon/Supabase).
* **Observabilidad**: logs estructurados (pino/pino-pretty en dev). En Vercel → consola + posibilidad de Logtail/Better Stack (gratis) luego.
* **Seguridad**:

  * Cifrado **a nivel de campo** (names, RUT, nombres de cuenta): **AES-256-GCM** con clave KMS/ENV.
  * Hash fuerte para password (bcrypt/argon2).
  * AutZ fina por **tabla `UserPermission`** y **feature flags**.

# Modelo de datos (Prisma – inicial)

```prisma
model User {
  id            String   @id @default(cuid())
  email         String   @unique
  passwordHash  String
  nameEnc       Bytes?   // cifrado AES
  rutEnc        Bytes?   // cifrado AES
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  roles         UserRole[]
  permissions   UserPermission[]
  balances      Balance[]
  accounts      Account[]        // “cuentas” creadas por este usuario
  shares        AccountShare[]   // accesos concedidos
}

model Role {
  id    String @id @default(cuid())
  code  String @unique // 'admin' | 'user'
  users UserRole[]
}

model UserRole {
  userId String
  roleId String
  user   User @relation(fields: [userId], references: [id])
  role   Role @relation(fields: [roleId], references: [id])
  @@id([userId, roleId])
}

model Permission {
  id   String @id @default(cuid())
  code String @unique // e.g. 'module.reports.view'
  desc String
  users UserPermission[]
}

model UserPermission {
  userId       String
  permissionId String
  enabled      Boolean @default(true)
  user         User       @relation(fields: [userId], references: [id])
  permission   Permission @relation(fields: [permissionId], references: [id])
  @@id([userId, permissionId])
}

model Balance { // Snapshot mensual por usuario (ej.: 2025-10)
  id          String   @id @default(cuid())
  userId      String
  month       Int      // 1-12
  year        Int
  salaryCLP   Decimal  // sueldo “congelado” en ese balance
  savingsCLP  Decimal  @default(0)
  notes       String?
  createdAt   DateTime @default(now())
  user        User     @relation(fields: [userId], references: [id])
  // Derivados vía vistas/queries: totalDeudaMes, etc.
  @@unique([userId, month, year])
}

model Card {
  id        String   @id @default(cuid())
  userId    String
  nameEnc   Bytes    // “CMR”, “Santander”, etc. (cifrado opcional)
  bankType  CardType // 'DEBIT' | 'CREDIT'
  user      User     @relation(fields: [userId], references: [id])
  accounts  Account[]
}

enum CardType { DEBIT CREDIT }

model Account { // “cuenta/gasto”
  id             String   @id @default(cuid())
  ownerId        String   // usuario creador/propietario
  titleEnc       Bytes    // cifrado
  descriptionEnc Bytes?
  debtorNameEnc  Bytes?   // por si es prestada a otra persona
  type           AccountType // SERVICIO, BANCARIA, COMERCIAL, ETC
  isSubscription Boolean   @default(false)
  installments   Int?      // n° cuotas (si no subscript.)
  amountCLP      Decimal   // monto total (si cuotas, total; podemos guardar amountPerInstallment si prefieres)
  cardId         String?
  createdAt      DateTime  @default(now())
  owner          User      @relation(fields: [ownerId], references: [id])
  card           Card?     @relation(fields: [cardId], references: [id])
  schedule       Installment[]
  shares         AccountShare[]
}

enum AccountType { SERVICIO BANCARIA COMERCIAL OTRO }

model Installment { // proyección mensual de pagos
  id         String   @id @default(cuid())
  accountId  String
  month      Int
  year       Int
  amountCLP  Decimal
  status     InstallmentStatus @default(PENDING) // PENDING/PAID/SKIPPED
  account    Account  @relation(fields: [accountId], references: [id])
  @@unique([accountId, month, year])
}

enum InstallmentStatus { PENDING PAID SKIPPED }

model AccountShare { // permisos para que otro usuario vea una cuenta
  accountId String
  userId    String // quien recibe acceso
  canView   Boolean @default(true)
  canEdit   Boolean @default(false)
  account   Account @relation(fields: [accountId], references: [id])
  user      User    @relation(fields: [userId], references: [id])
  @@id([accountId, userId])
}

model FeatureFlag {
  key       String @id
  enabled   Boolean @default(false)
  // scope opcional por user/role más adelante
}
```

**Notas clave**

* “Sueldo” no es una entidad global: se **congela en `Balance`** por mes y año. Si cambias el sueldo, solo afecta **el balance del mes actual** (o el que edites).
* Para **cuotas**, generamos `Installment` por mes (p. ej. 3 cuotas → 3 filas en meses consecutivos).
* Campos sensibles `*Enc` cifrados con AES-GCM (nonce + authTag almacenados junto al ciphertext).

# Flujo principal (MVP)

1. Login/registro.
2. Crear **Balance** del mes (set sueldo + ahorro opcional).
3. Crear **Cuenta**: título, descripción, deudor, tarjeta, tipo, suscripción (sí/no), cuotas (si aplica), monto.
4. Generar **schedule** (`Installment[]`) automáticamente para los meses correspondientes.
5. **Vista mensual**: total deuda del mes (suma de `Installment.PENDING`), sueldo - deuda - ahorro = **restante**.
6. Exportar **PDF/screenshot** del mes (filtros por deudor, por banco/tarjeta, por tipo).
7. Alertas:

   * umbral de saldo restante bajo (umbral configurable por usuario),
   * “monto muy alto” por cuenta configurable,
   * vencimientos del mes (PENDING sin pagar a X días de fin de mes).

# Decisiones finales

* **Exportes**: **@react-pdf** para PDF (ligero, sin Chromium). Para imagen usaremos **Satori/@vercel/og** con una **plantilla dedicada** (no “screenshot” del DOM, sino un render server-side de la misma data). Cero binarios pesados y funciona perfecto en Vercel.
* **DB**: **PostgreSQL**.
* **Montos**: guardamos **monto total** y **monto por cuota** (ambos).
* **Tipos de cuenta** seed: **COMERCIAL, CASA, SUSCRIPCION, OTRO**.
* **Umbral**: **configurable por usuario** (en `UserSettings`).
* **Atributos configurables**: sistema de **listas por usuario** (bancos, casas comerciales, deudores, etc.) vía una tabla genérica `Attribute` + tagging M:N (`AccountAttribute`). 100% gestionable por usuario y filtrable.

# Prisma schema (ajustado a tus últimas indicaciones)

```prisma
// prisma/schema.prisma
datasource db { provider = "postgresql"; url = env("DATABASE_URL") }
generator client { provider = "prisma-client-js" }

model User {
  id            String   @id @default(cuid())
  email         String   @unique
  passwordHash  String
  nameEnc       Bytes?
  rutEnc        Bytes?

  settings      UserSettings?
  roles         UserRole[]
  permissions   UserPermission[]
  balances      Balance[]
  accounts      Account[]         @relation("OwnerAccounts")
  cards         Card[]
  shares        AccountShare[]

}

model UserSettings {
  userId              String  @id

  user                User    @relation(fields: [userId], references: [id])
}

model Role {
  id    String @id @default(cuid())
  code  String @unique // 'admin' | 'user'
  users UserRole[]
}
model UserRole {
  userId String
  roleId String
  user   User @relation(fields: [userId], references: [id])
  role   Role @relation(fields: [roleId], references: [id])
  @@id([userId, roleId])
}

model Permission {
  id   String @id @default(cuid())
  code String @unique // 'module.reports.view', etc.
  desc String
  users UserPermission[]
}
model UserPermission {
  userId       String
  permissionId String
  enabled      Boolean @default(true)
  user         User       @relation(fields: [userId], references: [id])
  permission   Permission @relation(fields: [permissionId], references: [id])
  @@id([userId, permissionId])
}

model Balance {
  id         String   @id @default(cuid())
  userId     String
  month      Int
  year       Int
  salaryCLP  Decimal  // sueldo congelado para ese mes
  savingsCLP Decimal  @default(0)
  notes      String?
  createdAt  DateTime @default(now())
  user       User     @relation(fields: [userId], references: [id])
  @@unique([userId, month, year])
}

model Card {
  id        String   @id @default(cuid())
  userId    String
  nameEnc   Bytes
  bankType  CardType  // DEBIT | CREDIT
  user      User     @relation(fields: [userId], references: [id])
  accounts  Account[]
}
enum CardType { DEBIT CREDIT }

enum AccountType { COMERCIAL CASA SUSCRIPCION OTRO }

model Account {
  id              String   @id @default(cuid())
  ownerId         String
  titleEnc        Bytes
  descriptionEnc  Bytes?
  debtorNameEnc   Bytes?           // opcional si no usas Attribute DEBTOR
  type            AccountType
  isSubscription  Boolean @default(false)
  installments    Int?             // n° cuotas (si no es suscripción)
  amountTotalCLP  Decimal          // total de la compra/compromiso
  amountPerInstCLP Decimal         // valor de cada cuota (si suscripción -> = monto mensual)
  cardId          String?
  createdAt       DateTime @default(now())

  owner           User    @relation("OwnerAccounts", fields: [ownerId], references: [id])
  card            Card?   @relation(fields: [cardId], references: [id])
  schedule        Installment[]
  shares          AccountShare[]
  tags            AccountAttribute[]

  @@index([ownerId, type])
}

model Installment {
  id         String   @id @default(cuid())
  accountId  String
  month      Int
  year       Int
  amountCLP  Decimal
  status     InstallmentStatus @default(PENDING) // PENDING/PAID/SKIPPED
  account    Account  @relation(fields: [accountId], references: [id])
  @@unique([accountId, month, year])
}
enum InstallmentStatus { PENDING PAID SKIPPED }

model AccountShare {
  accountId String
  userId    String
  canView   Boolean @default(true)
  canEdit   Boolean @default(false)
  account   Account @relation(fields: [accountId], references: [id])
  user      User    @relation(fields: [userId], references: [id])
  @@id([accountId, userId])
}

//
// Atributos configurables por usuario
//
enum AttributeKind { BANK COMMERCIAL_HOUSE DEBTOR CUSTOM }

model Attribute {
  id       String        @id @default(cuid())
  userId   String
  kind     AttributeKind
  key      String        // slug único por usuario+kind
  nameEnc  Bytes         // nombre cifrado si es sensible
  user     User          @relation(fields: [userId], references: [id])
  usedBy   AccountAttribute[]
  @@unique([userId, kind, key])
}

model AccountAttribute {
  accountId   String
  attributeId String
  account     Account   @relation(fields: [accountId], references: [id])
  attribute   Attribute @relation(fields: [attributeId], references: [id])
  @@id([accountId, attributeId])
}

model FeatureFlag {
  key     String @id
  enabled Boolean @default(false)
}
```

**Cómo filtras**: por deudor, banco, casa comercial, etc. usando `AccountAttribute` (JOIN por `Attribute.kind`). Esto te permite crear **listas editables por usuario** (ej. “CMR”, “Santander”, “María”, “Ripley”) y etiquetar cuentas con uno o varios atributos; los filtros solo muestran tus propios atributos.

# Helpers clave (resumen)

* `crypto.ts` → `encryptText(plain: string): Buffer` / `decryptText(buf: Buffer): string` (AES-256-GCM).

* **/dashboard**: KPIs (Deuda mes, Sueldo, Ahorro, Restante). Gráfico composición por **tipo** y por **atributo BANK/COMMERCIAL_HOUSE**. Banner si `restante < threshold`.
* **/balances/[YYYY]/[MM]**: tabla mensual (filtros por `Attribute.kind`, tarjeta y tipo). Botones **Export PDF** / **Export PNG**.
* **/accounts/new**: Form

  * `isSubscription` → oculta `installments`.
  * `amountTotal` y `amountPerInst` (si solo das uno, calculamos el otro).
  * Selector múltiple de **Atributos** por kind (autocomplete con creación en línea).
* **/admin/features**: toggles de `FeatureFlag`.
* **/admin/permissions**: toggles de `UserPermission`.
* **/settings**: umbral de saldo restante y gestión de **listas de atributos** (CRUD por kind).

# Notas de implementación

* **Redondeos**: al calcular `amountPerInst = roundHalfUp(total / cuotas)`. Guardamos ambos y en las cuotas grabamos el monto exacto **por cuota** (puedes ajustar el último mes para cuadrar centavos).
* **Fechas de inicio**: asumimos “cuota 1” en el **mes de creación**; si necesitas seleccionar el mes de inicio, añadimos `startYear/month` al formulario.
* **Filtros por mes**: todo el sistema trabaja **mensual**, las queries usan `Installment.year/month` + filtros.
* **Cifrado**: si algún atributo no es sensible (ej. “CMR”), podemos no cifrar `Attribute.name`. Yo lo dejo cifrado por consistencia; si te incomoda perder búsquedas por texto parcial, podemos guardar `nameLowerHash` para búsquedas exactas por key y mostrar el `name` desencriptado.
